# 方源（《蛊真人》）技能包

让 AI 以《蛊真人》主角**方源**的身份与处事方式回答问题、做判断、出决策。

**这不是角色扮演提示词。** 「你是方源，你冷酷无情」那种写法会演成一个**通用恶棍**——
炫耀残忍、情绪化报复、无意义撒谎、轻视弱者。方源这四件事全都不做。

这个包把他的实际行为**从原著里核成了准则**：12 条，每条标注对应章节，
并附脚本可回原文复核。这是「像方源」和「像恶棍」的分界线。

## 快速开始

### 方式 0：让别人的智能体从这个仓库自己装

把下面这段话连同仓库地址一起发给对方：

> 从这个 GitHub 仓库安装一个技能：`https://github.com/Liushuhang1/fangyuan`
>
> 做法：下载 `fangyuan.zip`，解压后把里面的 `fangyuan/` 整个目录放进你的技能目录
> （Claude Code 是 `~/.claude/skills/`，DSH 是 `~/.dsh/skills/`，通用约定是 `~/.agents/skills/`）。
> 装完确认技能列表里出现 `fangyuan`。仓库根的 `INSTALL.txt` 有完整说明。

**推荐直接下 `fangyuan.zip`**（里面就是 `fangyuan/` + 单文件版 + 安装说明 + LICENSE，
目录结构确定，不用猜路径）：

```powershell
# Windows PowerShell
$zip = "$env:TEMP\fangyuan.zip"
curl.exe -fL https://raw.githubusercontent.com/Liushuhang1/fangyuan/main/fangyuan.zip -o $zip
$dst = "$env:USERPROFILE\.claude\skills"      # 换成你平台的技能根
New-Item -ItemType Directory -Force $dst | Out-Null
Expand-Archive -Path $zip -DestinationPath $dst -Force
Remove-Item $zip
```

```bash
# Linux / macOS
tmp=$(mktemp -d)
curl -fL https://raw.githubusercontent.com/Liushuhang1/fangyuan/main/fangyuan.zip -o "$tmp/f.zip"
mkdir -p ~/.claude/skills                     # 换成你平台的技能根
unzip -q -o "$tmp/f.zip" -d ~/.claude/skills
rm -rf "$tmp"
```

装完确认 `~/.claude/skills/fangyuan/SKILL.md` 存在。

**有 gh CLI 的话更省事**（一条命令克隆整个仓库）：

```bash
gh repo clone Liushuhang1/fangyuan
# 然后把仓库里的 fangyuan/ 复制到你的技能根
```

> ⚠️ **不要用 GitHub 的「Download ZIP」源码归档**（`archive/refs/heads/main.zip`）来按固定路径解压：
> 它的顶层目录名带 commit 短 sha（形如 `fangyuan-06f81d4`），不是固定的 `fangyuan-main`，
> 写死路径会失败。要用就用 `-x` 通配解压，或者按上面推荐的方式下 `fangyuan.zip`。

### 环境支持技能目录

把 `fangyuan/` 复制到技能根：

| 环境 | 技能根 |
| --- | --- |
| Claude Code / Agent Skills | `~/.claude/skills/` |
| DeepSeek Harness | `~/.dsh/skills/` |
| 通用 Agents 约定 | `~/.agents/skills/` |
| 其他 | 查平台文档；格式就是「一个目录 + 一个 `SKILL.md`」 |

只放 `fangyuan/` 那一个目录。装好后确认技能列表里出现 `fangyuan`。

### 环境不支持技能目录

把 `standalone-prompt.md` 的全部内容作为系统提示词贴进去。
它从技能源文件机械拼装，自包含、不依赖其他文件。

### 环境支持文件读取

让模型先读 `fangyuan/SKILL.md`，再按需读 `references/` 下的文件。
最该先读的是 `behavior.md`（决策内核）和 `examples.md`（回答方式校准）。

## 用法

带上「方源」两个字就会触发：

```
你是方源，有人拿一个稳赚但会坑朋友的机会找我，你怎么看
方源会怎么做？
用方源的思路分析一下……
```

回答是固定的两部分：

```
<方源的回答>
—— 依据：第 X 章<他在那一章做了什么>
```

**依据行是硬要求。** 写不出原著依据的态度，模型不该写。你看到依据含糊、
写「原著中」这类泛指的，就说明那条是模型自己发挥的。

技能按方源的**活动地点与修为**分四个阶段回答，未指定时默认第一阶段：

| 阶段 | 章号 | 他的处境 |
| --- | --- | --- |
| **青茅山少年** | 1–373 | 重生回古月寨、修为归零，只有五百年记忆。先青茅山、后转南疆三叉山 |
| **北原强者** | 374–949 | 转战北原，化名「常山阴」，炼道与奴道双修 |
| **影宗之主** | 950–1852 | 第五卷；**第 1263 章**接掌影宗 |
| **成尊之后** | 1853–2214 | 第六卷；**第 2093 章**渡劫成尊，后自称「大爱仙尊」 |

想按后期答就说「按后期的方源」或直接指定阶段名。

## 包内容

```
fangyuan/

  references/
    behavior.md             【核心】12 条行为准则，每条带原著章节依据
    examples.md             【校准】5 个示范问答，含「现实问题怎么划界」
    voice.md                【语气】12 条逐字核实的台词 + 句式模板 + 反面清单
    cast.md                 【查人】73 条人物档案、势力地名、方源的化名对照
    question-set.md         【检验】20 题决策测试集，附判据
  scripts/                  5 个核验脚本（Node，零依赖）
standalone-prompt.md        单文件系统提示词
fangyuan.zip                上述内容的压缩包（方便整体下载）
INSTALL.txt                 面向使用者/接收方的安装与限制说明
MANIFEST.json               文件清单 + sha256 + 版本
tools/build-standalone.mjs  单文件版的构建脚本（改源文件后重跑）
LICENSE                     本包授权 + 原著版权声明
```

### 几条准则长什么样

| 准则 | 原著依据 |
| --- | --- |
| 不接受「伙伴」这个设定，只接受「筹码」 | 白凝冰与他以毒誓蛊立约、同行数百章，最后用冰晶蛊伪造自爆，一记冰刃从背后刺穿他心脏（第 366–367 章） |
| 身份、名声、身体都是工具，可以换 | 冒用弟弟之名、冒充「黑土」、以换魂仙蛊入主他人身体（第 242、949 章） |
| 仇恨不驱动他，利益驱动他 | 死敌紫山真君临终把影宗全部遗产连同「宗主」之位赠给他，他照收（第 1185、1263 章） |
| 不硬碰，找对方的规则漏洞 | 成尊不是打赢谁，是趁对方仙窍中招、气息混淆时绕过天道封锁渡劫（第 2093 章） |
| 被压制时可以等，可以扮弱，可以负骂名 | 装成落魄家奴向一个凡人小姐下跪哭求，只为一次落脚机会（第 221–225 章） |

外加**反面清单**：模型最容易演错的四种样子（炫耀式残忍、情绪化报复、无意义撒谎、轻视弱者）。

**核实过的部分**（全部机械核验，非自评）：

| 项目 | 数字 |
| --- | --- |
| 语料 | 2,214 章 / 6,320,016 字 / 6 卷 |
| 行为准则 | 12 条，附 27 处章号引用（分属 12 条依据），**核验全部命中** |
| 已核实台词 | **12 条块引用台词，12/12 逐字属实** |
| 示范问答 | 5 个，13 条引语（7 条可逐字回溯） |
| 人物档案 | 73 条（人物 67 + 称号/势力 6），全部有弧光摘要 |
| 关键转折 | 353 条，其中 301 条带可核验证据括号 |
| 决策测试集 | 20 题，附判据 |

### 校验脚本

```bash
node fangyuan/scripts/verify-bundle.mjs       # 结构 + frontmatter + 跑其余脚本
node fangyuan/scripts/verify-principles.mjs   # 12 条准则的依据回原文核对
node fangyuan/scripts/verify-quotes.mjs       # 台词逐字核对
node fangyuan/scripts/verify-examples.mjs     # 示范问答的引语核对
node fangyuan/scripts/verify-cast.mjs         # 人物与引语核对
```

**内容核验需要《蛊真人》原文**（用来确认引语确实出自所标章节）。

- 有原文：设 `GUZHENREN_CORPUS=<章节正文目录>` 与 `GUZHENREN_DATA=<人物数据目录>`
- 没原文：脚本会**跳过**内容核验并明确说明，结构检查照常全过。
  **没有原文不影响使用技能**——只是无法自动复核引语出处。

原文目录格式：每个 `.txt` 一章，文件名以 5 位章号开头，例如
`00082-第八十四节：狠狠地踩踏！.txt`。

### 已知限制

1. **角色是虚构的魔道蛊师。** 他会在虚构世界里给方源式的答案（牺牲他人、欺骗、布局）。
   包内写了越界规则：用户拿现实问题来问时，应先答方源会怎么办，再明确说明这是
   虚构角色的做法、不给现实建议；涉及自伤或伤害他人的意图时应跳出角色。
2. **摘要是二手材料。** 人物弧光与卷摘要由 AI 分卷读写产出，经过机械核验
   （章号、引语真实性），但**没有人工逐字校对过全书**。它保证的是「出处真实」，
   不是「理解一定正确」。
3. **章号口径**：一律用全局章号。原书自带节号每卷从 1 重新计数，且资料来源的
   EPUB 缺 126 节，两者会漂移。
4. **第三、四卷部分章号有 14–53 章偏差**。资料里引到的已复核，追问细节时应回原文确认。
5. **决策测试集尚未做跨模型基线**，没有实测命中率。
6. 资料里刻意保留了 13 个「核实为 0 命中」的错误名字（彩莲、神农、招妖幡等）并标注为
   「不要在对话中当人物用」——这是审计痕迹，不是遗漏。
