方源技能包 v1.0.0 — 安装说明
================================================

这个压缩包里是一套「让 AI 以《蛊真人》主角方源的身份与处事方式回答问题」的指令包。

它和「你是方源，你冷酷无情」那种角色扮演提示词不同：方源的实际行为被从原著里
核成了准则，每条准则都标注了对应章节，并附脚本可回原文复核。避免模型演成一个
通用恶棍（炫耀残忍、情绪化报复、无意义撒谎、轻视弱者——方源这四件事都不做）。


一、包内容
------------------------------------------------

    fangyuan/                      技能本体（要装的就是这个目录）
      SKILL.md                     入口：三条硬规矩 + 阶段判断 + 越界规则
      references/
        behavior.md                12 条行为准则，每条带原著章节依据
        examples.md                5 个示范问答（含「现实问题怎么划界」）
        voice.md                   13 条逐字核实的台词 + 句式模板 + 反面清单
        cast.md                    73 条人物档案、势力地名、方源的化名对照
        question-set.md            20 题决策测试集，附判据
      scripts/                     5 个核验脚本（Node，零依赖）
    standalone-prompt.md           单文件系统提示词（不支持技能的用这个）
    README.md                      详细说明：数据来源、覆盖度、已知限制
    MANIFEST.json                  文件清单 + sha256 + 版本
    INSTALL.txt                   本文件


二、装法（按你的环境挑一种）
------------------------------------------------

【方式 A】环境支持「技能 / skill」目录

  把 fangyuan/ 这个目录整体复制到技能根。常见位置：

    Claude Code / Agent Skills    ~/.claude/skills/    或  <项目>/.claude/skills/
    DeepSeek Harness (DSH)        ~/.dsh/skills/       或  <项目>/.dsh/skills/
    通用 Agents 约定               ~/.agents/skills/    或  <项目>/.agents/skills/
    其他平台                      查平台文档；格式就是「一个目录 + 一个 SKILL.md」

  注意：只放 fangyuan/ 这一个目录。外层的 README.md、standalone-prompt.md、
  MANIFEST.json、本文件都不要放进技能根——它们是给人读的说明，放进去没用。

  装完后确认：技能列表里应该出现 fangyuan。
  没出现通常是两个原因：
    1) 放错目录（确认父目录名就是 skills）
    2) SKILL.md 顶部的 frontmatter 被改坏了 —— name 必须是 kebab-case
       （全小写，只能用连字符，不能有下划线、空格、大写）

【方式 B】环境不支持技能目录（只有一个对话框）

  把 standalone-prompt.md 的全部内容作为系统提示词（或对话开头的指令）贴进去。
  它是从技能源文件机械拼装的，自包含、不需要读别的文件。

【方式 C】环境支持文件读取 / 检索

  让模型先读 fangyuan/SKILL.md，需要时再按里面指的路去读 references/ 下的文件。
  最该先读的两份是 behavior.md（决策内核）和 examples.md（回答方式校准）。


三、怎么用
------------------------------------------------

装好后直接说带「方源」两个字的话就会触发，例如：

    你是方源，有人拿一个稳赚但会坑朋友的机会找我，你怎么看
    方源会怎么做？
    用方源的思路分析一下……

回答格式是固定的两部分：

    <方源的回答>
    —— 依据：第 X 章<他在那一章做了什么>

「依据」那一行是硬要求：写不出原著依据的态度，模型不该写。你看到依据行含糊、
写「原著中」这种泛指的，就说明那条是模型自己发挥的。

技能会分阶段回答（青茅山少年 1–373 章 / 影宗之主 374–949 / 成尊之后 950–2214），
你没指定时默认用青茅山少年那个阶段。想让它按后期答就说「按后期的方源」。


四、跑核验脚本会显示「跳过」，这是正常的
------------------------------------------------

包里的 5 个 Node 脚本用来机械复核引语和准则依据是否真实，但它们需要《蛊真人》
原文（2,214 章正文）才能核对出处。你的机器上大概率没有原文，于是：

    结构检查  → 照常全过
    内容核验  → 标记为「跳过」，不报错

这是设计好的降级行为（脚本用退出码区分：0 通过 / 2 缺数据 / 其他失败）。
技能本体完全不依赖原文，缺原文不影响使用。

如果你确实有原文，可以开启完整核验：

    格式约定：每个 .txt 是一章，文件名以 5 位章号开头
              例如 00082-第八十四节：狠狠地踩踏！.txt

    set GUZHENREN_CORPUS=<章节正文目录>
    set GUZHENREN_DATA=<人物数据目录>
    node fangyuan/scripts/verify-bundle.mjs

想快速检查结构（不跑内容核验）：

    node fangyuan/scripts/verify-bundle.mjs --quick


五、数据可靠性与限制（用之前该知道）
------------------------------------------------

核实过的部分：

    行为准则      12 条，附 27 处章号引用依据，核验全部命中
    已核实台词    12 条块引用台词，12/12 逐字属实
    示范问答      5 个，13 条引语（7 条可逐字回溯）
    人物档案      73 条（人物 67 + 称号/势力 6），全部有弧光摘要
    关键转折      353 条，其中 301 条带可核验证据

限制：

  1. 角色是虚构的魔道蛊师。他会在虚构世界里给方源式的答案（牺牲他人、欺骗、布局）。
     包内写了越界规则：用户拿现实问题（职场、感情、法律、健康）来问时，模型应先答
     方源会怎么办，再明确说明这是虚构角色的做法、不给现实建议。涉及自伤或伤害他人
     的意图时应跳出角色。但使用者仍需自行判断。

  2. 人物弧光与卷摘要由 AI 分卷读写产出，经过机械核验（章号、引语真实性），
     但没有人工逐字校对过全书。它保证的是「出处真实」，不是「理解一定正确」。
     当作有据可查的二手材料。

  3. 章号一律用「全局章号」（按阅读顺序数出来的）。原书自带的节号每卷从 1 重新计数，
     且资料来源的 EPUB 缺 126 节，两者会漂移。不要拿节号去对全局章号。

  4. 第三、四卷的部分章号有 14–53 章偏差。技能资料里引到的都已复核，
     但若追问这两个卷的细节章号，应回原文确认而不是直接答。

  5. SKILL.md 里提到的语料路径（E:\zhengliu\...）是产出机器的路径，你这边不存在。
     技能里已写明处理方式：路径不存在时直接用自带的 references/，不要顺着用户的
     描述编原著情节。

  6. 决策测试集（question-set.md 的 20 题）有判据、但尚未做跨模型基线，
     没有实测命中率数据。

  7. 技能资料里刻意保留了 13 个「核实为 0 命中」的错误名字（彩莲、神农、招妖幡等），
     并标注为「不要在对话中当人物用」。这是审计痕迹，不是遗漏。
